What is Shortwind?

A token-efficient class layer for LLM-generated HTML. Flat vocabulary, no new grammar, distributed shadcn-style.

This page is the demo. It is written entirely in Shortwind shorthand — @card, @btn-primary, @heading-xl — and a single CDN script expanded it before first paint. Hit Ctrl+U to compare the source with the rendered DOM.

The problem

LLMs spend 35–50% of their HTML output tokens on Tailwind class strings. The same clusters — card shells, button variants, flex rows — get retyped utility-by-utility on every element, in every response.

Shortwind collapses those common clusters into 1–3-token recipes the model can memorise on turn one. A tiny expander rewrites each recipe to its canonical Tailwind classes before the browser (or build step) ever sees it. Same rendered output, roughly half the tokens.

How it works

1

LLM writes shorthand

Recipes prefixed with @ inside class="...", mixed freely with raw Tailwind utilities.

2

Expander resolves recipes

Each @name is replaced with its definition, nested references and all. Conflicts are settled by tailwind-merge — last position wins.

3

Tailwind sees only utilities

No runtime cost in production, no semantic change. Purge, JIT, and the dev server all work normally.

Using the CDN expander

For one-off HTML files — Claude artifacts, demos, single-page experiments — there is no install and no build step. One script tag is the whole integration: 

<script src="https://shortwind.dev/expand.js" defer></script>

On DOMContentLoaded the script walks the document, expands every @recipe in every class attribute, and stops. No mutation observer, no overhead after first paint. It ships the expander (~1KB gzipped) plus the default catalog of 100+ recipes, ~6KB gzipped total.

Need a custom palette? Point the script at a registry manifest:

<script
  src="https://shortwind.dev/expand.js"
  data-registry="https://my-registry.example/manifest.json"
  defer
></script>

Shipping a real site? Use the bundler plugin (@shortwind/vite, @shortwind/next, or @shortwind/astro) instead. It expands recipes at build time, so production output ships zero @ tokens and no runtime expander.
